# 分かったこと・本番化の課題（10/25 の見比べ用。下書き）

ステータス: 下書き（2026-10-22 メインエージェント作成）。実機での確認とデモの感想は、Kazuki が追記する。

## このプロトタイプの切り口
- **アルバムの販売で収益を上げる**。イベント単位の課金ではなく、現像後に自動でできる「ふたりの絵日記」を、ホストだけでなく**ゲストも買える**ようにした（デジタル版 ¥500 / 印刷版フォトブック ¥3,000。決済はモック）
- 撮影と現像は土台にとどめた。アプリ不要の QR 撮影、1人あたりの枚数制限、巻き上げ操作、ホストが押すまで写真が見られない「現像」
- 見た目: 撮影は黒の全画面のファインダー。現像後は白基調の、ゆるい手描きの絵日記

## 類似のアプリ・チームの試作との違い
- Pimorio（2026-10-14 v2.0.0）は、QR での参加・グループ合計の枚数・翌朝の一斉現像を、**無料・課金なし**で実現済み。想定は友達同士の集まり
- チームの1人の試作は、QR 撮影〜写真一覧まで
- このプロトタイプの差は、**結婚式・イベント向け**であることと、**現像後のアルバムを商品にして、参加者全員を買い手にする**課金の設計

## 作ってみて分かったこと
- **アプリ不要の撮影は、ブラウザだけで成り立つ**。QR → 「カメラをはじめる」→ OS の許可 → シャッターで、1枚目まで3タップ。ただし、カメラは HTTPS でしか動かない。iOS ではユーザーの操作をきっかけにしないとカメラを開始できないので、「はじめる」ボタンが1回必要
- **「撮った写真が見えない」は、確認の不安とセット**。カウンターの減り・暗転・巻き上げで「撮れた」実感を出した。会場の回線が悪いときに備えて、送信中の枚数の表示、再送、離脱の前の警告が必要だった
- **撮影中にホストが現像する場面**の扱いが必要だった（ゲストの画面を自動で切りかえる。現像直前に撮った写真は、署名の期限内なら受け付ける）
- **枚数の上限は、サーバー側で厳密に数える必要がある**（同時に送られても超えないよう、条件付きの INSERT で判定した）
- **写真の公開のタイミングを守るには、API 側での制御が必須**（現像前は、アルバムと画像の取得をホスト以外に許さない）
- アップロードは、写真を canvas で JPEG に変換してから送るので、**位置情報などの EXIF が自然に落ちる**（プライバシー面では利点）
- 見た目は5回ほど方向を変えた（現代の雑誌風 → 古いファッション雑誌 → カジュアル → カートゥーン → 絵日記）。**ターゲットと価格帯によって、刺さる見た目が大きく変わる**ので、見た目の検証は早めに、実際の写真で行うのがよい

## 未検証の仮説（デモの場で聞きたいこと）
- ゲストは、自分が撮っていない写真も含むアルバムに、お金を払うか。払うならいくらか
- デジタル版と印刷版のどちらが選ばれるか。価格（¥500 / ¥3,000）は妥当か
- 現像のタイミング（ホストのボタン／翌朝の自動）は、どちらが喜ばれるか
- 枚数制限は、1人ごと（今回）とグループ合計（Pimorio）のどちらがよいか
- 絵日記の見た目は、結婚式以外のイベントでも通用するか

## 本番化の課題
- **決済**: Stripe などの本物の決済、返金、領収書
- **印刷**: 印刷業者との連携（入稿データの生成、発送、問い合わせ）
- **現像の自動化**: 決まった時刻での自動現像（Cron Triggers）
- **ホストの認証**: 今はトークンを端末に保存するだけ。アカウント、複数ホスト、権限の回復の手段が必要
- **悪用への対策**: 誰でもイベントを作ってアップロードできる。レート制限、不適切な画像の検知、通報が必要
- **保存期間と費用**: チームの方針（保存期間1年）への対応。R2 の容量と操作回数の見積もり、期限後の削除
- **画像の処理**: サムネイルの生成、向きの補正、大量の写真の zip をサーバー側で作る
- **オフライン**: 未送信の写真を IndexedDB に保存し、ブラウザを閉じても失わない
- **アルバムの編集**: 写真の選択・並べ替え、ゲストのひとこと、イベントに合わせたテンプレート
- **実機での検証**: iPhone Safari と Android Chrome でのカメラ・スワイプ・PWA のインストール

## 技術メモ
- 構成: フロント（Vite + React、Worker の静的アセット）、API（Cloudflare Workers + D1 + R2）。費用は無料枠で収まる見込み
- 写真は、Worker が発行する期限付きの署名URLに、端末から直接アップロードする（R2 のキーを発行しなくて済む）
- テスト: API の通しテスト 20件、ブラウザでの確認（Playwright）、本番のスモークテスト（`tests/`）
