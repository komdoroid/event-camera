# 全体設計（UX）— 絵日記カメラ（さまざまなイベント向け）

ステータス: 案（2026-10-25 メインエージェント作成）。Kazuki の承認待ち
前提: **結婚式専用ではなく、さまざまなイベント（誕生日、飲み会・パーティー、同窓会、旅行、社内イベント、結婚式など）のためのサービス**として設計する（2026-10-25 Kazuki の指示）。本番の姿を設計し、各機能に「今日つくる（P0）／見せ方だけ（P1）／本番で（P2）」を付ける。今日は 10/25 の見比べに向けた仕上げ。

## 0. 設計の軸
1. **3人の主役**: ホスト（幹事・主催者・主役本人）、ゲスト（参加者）、そしてアルバムそのもの。ゲストは「アプリを入れない・登録しない」を守る
2. **撮る → 待つ → とどく → のこす** の4つの時間を、それぞれ気持ちよくする。とくに「待つ」と「とどく」は使い捨てカメラらしさの核
3. **買う理由を作る**: 「自分が撮った写真」「自分が写っている場」を見つけられること。押し売りはしない（最後のページで1回だけ聞く）
4. **どのイベントにも合う**: サービス名は「絵日記カメラ」、アルバムの基本の題名は「みんなの絵日記」。表紙の主役はイベント名。種類を選ぶと、名前の例・アイコン・ページのひとことが変わる（結婚式を選んだときだけ「ふたりの絵日記」）。種類を選ばなくても自然に使える
5. **ホストは迷わない**: 管理画面は「いまの段階（準備・撮影中・現像後）」に合わせて、次にやることを一番上に出す

## 1. ユーザーの旅（全体の流れ）

```
ホスト  : はじめて開く → しくみの紹介 → イベントをつくる → QRカードを印刷/共有
          → 当日：撮影の様子を見る（自分も撮る）→ 現像する → ゲストに知らせる
          → アルバムを見る/買う → 写真をダウンロード → 過去のイベントとして残る
ゲスト  : QRを読む → ようこそ（イベント名・ホストのひとこと・3つのルール）→ カメラ
          → 撮り切る/やめる → 待つ（とどいたら知らせる）→ とどいた → アルバム
          → 自分の写真をさがす → 手元にのこす（デジタル/印刷）→ 完了・共有
```

## 2. ゲスト

| 機能 | 体験 | 状態・例外 | 区分 |
| --- | --- | --- | --- |
| ようこそ画面 | QR の直後に、イベント名・ホストのひとこと・ルール3つ（「◯枚まで」「撮った写真は見えません」「現像されたら絵日記がとどく」）と「カメラをはじめる」。タップ数は今と同じ（3タップ以内） | 現像済みなら「とどきました」へ。存在しない ID なら「QR をもう一度読んでください」 | P0 |
| カメラ | 今のまま（黒の全画面、カウンター、グリッド、日付、巻き上げ）。Android はシャッターで短く振動 | 権限が拒否されたら、OS 別の戻し方（iPhone: 設定 → Safari → カメラ）を図つきで案内 | P0 |
| 送信の安心 | 「送信中 n 枚」。回線が戻れば自動で再送。閉じる前に警告 | 本番: 未送信を IndexedDB に保存し、次に開いたときに送る | P0（済）/P2 |
| 途中でやめる | 撮り切らなくても「今日はここまで」で待つ画面へ。あとで同じ QR から続きを撮れる | 残り枚数はサーバーで数える | P1 |
| 待つ画面 | 撮った枚数、イベント名、「現像されると自動で切りかわる」。ホーム画面への追加 or ブックマークをすすめる | 本番: 通知を受け取る（Web Push／メール／LINE を選ぶ） | P0 / P2 |
| とどいた | 「絵日記がとどきました」→ ひらく | 本番: 通知から直接ここへ | 済 |
| アルバム | 表紙 → ページ。下にページ番号（3 / 8）、左右スワイプでめくる。**自分が撮った写真に「あなたが撮った」の小さな手描きシール** | 写真の読み込み中は手描きの枠だけ出す。読み込み失敗はその枠に「もう一度」 | P0 |

## 3. ホスト

| --- | --- | --- | --- |

## 5. オンボーディング・共有
- ホーム画面への追加の案内は、**最初のイベントを作ったあと**に1回だけ出す（いきなり出さない）。P0
- サンプルの絵日記: 本番のサンプルイベント（誕生日パーティー・ガーデンBBQ・ウェディングパーティー）の公開アルバムを選んで見られる。チームの誰でも、鍵なしで「とどいたあと」の体験を見られる。P0
- チームへの共有用に、トップ（`/host`）から1タップで「この試作について」（しくみ・料金の仮説・未実装の範囲）を開ける。P1

## 6. 文言・見た目のルール
- ひらがな多め、手描きの線、淡い青とピンク。黒の全画面はカメラだけ
- ボタンの主従: 主はピンク塗り（`.hbtn.ghost` の現在の見た目）、従は白地。1画面に主ボタンは1つ
- エラーは「何が起きたか＋次に何をすればよいか」を1文ずつ。技術用語を出さない
- 文言は `diary/copy.ts` に集約し、イベントの種類で切りかえる。**共通の文言には、結婚式に寄った言葉（ふたり・新郎新婦・披露宴など）を使わない**
- アプリ名・manifest・タイトルは「絵日記カメラ」。アイコンも結婚式を連想させないものにする

## 7. API の追加（P0 に必要な分）
- イベントに `kind`（birthday / party / reunion / trip / company / wedding / other、既定 other）と `message`（任意、140字まで）を追加（D1 マイグレーション 0002）
- `POST /api/events` が `kind`・`message` を受け取る。`GET /api/events/:id` が `kind`・`message`・`coverPhotoId`（現像後、または鍵つきのとき）を返す
- （取り消し）売上はホストに返さない。開発者が D1 の orders を集計する
- `GET /api/events/:id/album?guestId=…` は、写真ごとに `mine: boolean` を返す（自分の写真かどうかだけ。ほかの人の guestId は返さない）
