# Claude Code マルチエージェント設定

メインエージェント（窓口）が意図をヒアリングしてタスクに分け、専門エージェントに任せて報告を受ける構成です。

```
ユーザー ⇄ メインエージェント（CLAUDE.md）
                ├─ frontend-dev   画面・UI
                ├─ backend-dev    API・DB・ストレージ
                ├─ qa-tester      動作確認・テスト
                └─ reviewer       レビュー（読み取り専用）
```

## 構成

| パス | 内容 |
| --- | --- |
| `CLAUDE.md` | メインエージェントの行動指針。`docs/project.md` を読み込む |
| `.claude/agents/*.md` | 専門エージェントの定義 |
| `.claude/settings.json` | 権限設定と環境変数 |
| `docs/project.md` | プロジェクト固有の情報（**リポジトリごとに書き換える**） |
| `docs/brief.md` | ヒアリング結果。メインエージェントが記入 |
| `docs/tasks.md` | タスク一覧。メインエージェントが管理 |

## 新しいプロジェクトで使う

1. このリポジトリをテンプレートにして新しいリポジトリを作る（GitHub の「Use this template」）
2. `docs/project.md` を埋める（技術スタック・ディレクトリ・コマンド）
3. 必要に応じて `.claude/settings.json` にプロジェクト固有のコマンドを追加する
4. リポジトリのルートで `claude` を起動し、作りたいものを伝える

## 動き方

1. ヒアリング → `docs/brief.md` にまとめて承認をもらう
2. タスク分解 → `docs/tasks.md`
3. 専門エージェントに委任（触るファイルが重ならないものは並列）
4. 報告を検証 → qa-tester・reviewer で確認 → ユーザーに報告

デプロイ・外部サービス登録・課金が絡む操作は、必ずユーザーに確認してから行います。

## 設定メモ

- `CLAUDE_CODE_FORK_SUBAGENT=0`：メインエージェントが会話をまるごと複製した fork ではなく、定義済みの専門エージェントに委任するようにし、結果を待てるようにしています
- 専門エージェントは `Agent` ツールを持たないため、さらに下のエージェントは作りません
- 汎用設定を更新したら、プロジェクト側にも手で反映してください
